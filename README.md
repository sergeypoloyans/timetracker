# Учёт рабочего времени

Небольшое веб-приложение для учёта рабочего времени сотрудников.

Что умеет:
- добавлять сотрудников;
- запускать и останавливать таймер с описанием задачи;
- показывать записи и общее время каждого сотрудника за выбранный период;
- сохранять данные между перезапусками (база SQLite в файле `timetracker.db`).

Все имена и задачи в примерах и тестах вымышленные.

## Стек

- **Python 3.10+** и **Flask** — сервер и JSON API.
- **SQLite** — база данных в одном файле, отдельный сервер базы не нужен.
- **HTML + CSS + JavaScript** без фреймворков — интерфейс.
- **pytest** — автоматические проверки.

## Запуск

```bash
git clone <ссылка на репозиторий>
cd timetracker

python -m venv .venv
# Windows:      .venv\Scripts\activate
# macOS/Linux:  source .venv/bin/activate

pip install -r requirements.txt
python app.py
```

Откройте в браузере http://127.0.0.1:5000

Данные хранятся в файле `timetracker.db` рядом с `app.py`. Другой путь можно задать
переменной окружения `TIMETRACKER_DB`.

## Проверки

```bash
python -m pytest -v
```

17 тестов покрывают основные сценарии:

| Сценарий | Тест |
|---|---|
| Добавление сотрудника, пустое имя, дубликат имени | `test_add_employee_and_list`, `test_empty_name_is_rejected`, `test_duplicate_name_is_rejected` |
| Запуск и остановка таймера | `test_start_and_stop_timer` |

| **Повторный запуск после остановки** — новая запись | `test_restart_after_stop_creates_new_entry` |
| Остановка без запуска, запуск без описания, неизвестный сотрудник | `test_stop_without_start_is_rejected`, `test_start_requires_description`, `test_unknown_employee` |
| **Пустой отчёт** — пустой список записей и нулевые итоги, а не ошибка | `test_empty_report` |
| Фильтр по периоду, последний день периода, итоги по сотрудникам | `test_report_filters_by_period`, `test_report_includes_whole_last_day`, `test_report_totals_per_employee` |

В тестах время подменяется (`FakeClock`), поэтому они не зависят от того, когда их запускают,
и не ждут реальные минуты.

### API

| Метод | Адрес | Что делает |
|---|---|---|
| GET | `/api/employees` | список сотрудников и их запущенные таймеры |
| POST | `/api/employees` | добавить сотрудника `{"name": "..."}` |
| POST | `/api/employees/<id>/start` | запустить таймер `{"description": "..."}` |
| POST | `/api/employees/<id>/stop` | остановить таймер |
| GET | `/api/report?from=ГГГГ-ММ-ДД&to=ГГГГ-ММ-ДД` | записи и итоги за период (обе даты включительно) |

### Ключевые решения

- **Один запущенный таймер на сотрудника.** Это проверяется дважды: в коде (понятная ошибка 409)
  и в базе через уникальный частичный индекс `one_running_timer`. Даже при двух одновременных
  запросах второй таймер не создастся.
- **Запущенный таймер хранится в базе** (запись с `end_time = NULL`), а не в браузере.
  Поэтому он переживает перезапуск сервера и закрытие вкладки.
- **Текст от пользователя выводится через `textContent`**, а не `innerHTML`.
  Имя вроде `<script>...` покажется как текст и не выполнится.

### Ограничения

- Время записывается по часам сервера (местное время). Для локального запуска этого достаточно;
  для работы в разных часовых поясах нужно хранить время в UTC.
- В отчёт попадают только завершённые записи. Запись относится к дню, когда таймер запустили.

   я смогу объяснить: Flask + SQLite, без фреймворков на фронтенде).
2. Генерация первой версии бэкенда и **тестов по требованиям задания**. Тесты писались

3. Ревью кода и ручная проверка интерфейса в браузере — ещё несколько ошибок.
4. Вопросы к ИИ по каждому файлу, чтобы разобраться, как работает код.

## Найденные и исправленные ошибки

Первую версию кода сгенерировал ИИ. Ошибки нашли тесты, ревью и ручная проверка в браузере.

1. **Записи за последний день периода не попадали в отчёт.**
   Время хранится строкой `'2026-11-02 15:00:00'`, а фильтр сравнивал её с `'2026-11-02'`.
   При сравнении строк первая «больше», поэтому весь последний день выпадал.
   *Исправление:* фильтр `start_time >= начало первого дня AND start_time < начало дня после последнего`.
   *Нашёл тест:* `test_report_includes_whole_last_day`.

2. **Таймер дольше суток считался неправильно.** Использовалось `(end - start).seconds`.
   Это не «всего секунд», а только секунды без учёта целых дней: 26 часов превращались в 2 часа.
   *Исправление:* `int((end - start).total_seconds())`.
   *Нашёл тест:* `test_long_entry_over_24_hours`.

3. **В итогах отчёта не было сотрудников без записей**, хотя нужно общее время *каждого*
   сотрудника. Пустой отчёт возвращал пустые итоги вместо нулей.
   *Исправление:* сначала всем сотрудникам ставится 0, потом прибавляется время записей.
   *Нашёл тест:* `test_empty_report`.

4. **Двойной клик по «Старт» мог уронить сервер с ошибкой 500.** Два почти одновременных
   запроса оба проходили проверку «таймер не запущен», и второй упирался в уникальный индекс базы.
   *Исправление:* перехват `sqlite3.IntegrityError` при вставке → понятный ответ 409.
   *Нашло:* ревью кода.

5. **Набранный текст стирался.** Если ввести задачу у одного сотрудника, а потом нажать «Старт»
   у другого, список перерисовывался, и введённый текст пропадал.
   *Исправление:* перед перерисовкой значения полей запоминаются, после — возвращаются.
   *Нашла:* ручная проверка в браузере.

6. **Отчёт не обновлялся после остановки таймера** — новую запись было видно только после
   повторного нажатия «Показать». *Исправление:* после «Стоп» отчёт перезагружается.
   *Нашла:* ручная проверка в браузере.
